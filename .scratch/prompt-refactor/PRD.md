# PRD: Prompt Template Refactoring & Assertion Group Extension

- **Status**: `ready-for-agent`
- **Created**: 2026-06-29

---

## Problem Statement

The current LLM prompt system has several structural problems:

1. **Few-shot examples are hardcoded in Java.** In `AssertionService`, few-shot conversation examples are inline `List<ChatMessage>` literals containing hand-written XML. This makes them difficult to read, edit, and version independently of code. Non-technical prompt engineers cannot iterate on them without a developer.

2. **XML conversion logic is duplicated in three places.** `SessionComplete.buildLabeledMessages()`, `MemoryCueAgent.buildLabeledMessages()`, and `MemoryCueAgent.buildSegmentText()` all produce identical `<turn>` XML. Changes to the XML format require coordinated edits across files.

3. **Few-shot examples and real conversation data use different XML construction paths.** The few-shot examples have their XML hand-crafted as string literals, while real data is generated by `buildLabeledMessages()`. There is no guarantee they stay consistent.

4. **Prompt files combine system and user template with a `---USER---` delimiter.** This convention obfuscates the file purpose, requires String split everywhere, and prevents clean per-file loading. All 6 non-streaming agents use this pattern.

5. **Assertion extraction is hardcoded to a single group.** `AssertionService.generateAssertionsAsync()` always queries `error-pattern` regardless of conversation mode. New groups (e.g., for daily standup content) require code changes.

## Solution

### Core Abstraction: `ExampleMsgFormatter`

A new static utility class in the `agent.common` package that centralizes:

- **Conversation-to-XML conversion**: `toXml(List<MessageData>)` and `toXmlUserOnly(List<MessageData>)` replace all duplicated `buildLabeledMessages` methods.
- **Few-shot template parsing**: `parseFewShot(String content, boolean userOnly)` reads a human-friendly `.txt` format and produces `List<ChatMessage>` ready for `LlmTaskDefinition`.

### Few-Shot Template Format

Human-readable conversation blocks with `User:` / `Assistant:` prefixes, separated by `---`:

```
User: Yesterday I go to the park.
Assistant: Ah, you went to the park? Was it crowded?
User: No, but I forget my key there.
Assistant: Oh no, you forgot your key? Hope you got it back.
---
["past tense"]
---
User: I have a idea for the meeting.
...
```

- Odd blocks (0-indexed) = conversation → internally parsed to `List<MessageData>` → `toXml()` → wrapped in `UserMessage`
- Even blocks = AI expected output → wrapped in `AiMessage`
- The `userOnly` flag controls whether assistant turns appear in the XML

### Prompt Directory Restructure

Each LLM task gets its own subdirectory. The `---USER---` delimiter is removed; system and user templates are separated:

```
prompts/
  correction/system.txt
  memory-profile/system.txt
  memory-cue/split/system.txt
  memory-cue/entry/system.txt
  report/system.txt
  assertion/
    extract-topics/{system.txt, examples.txt}
    extract-state/system.txt
    judge-same/{system.txt, examples.txt}
    merge-assertion/system.txt
  workplace_standup/...  (unchanged)
  daily_talk/...         (unchanged)
  japanese_business/...  (unchanged but ---USER--- removed from report.txt)
```

The `userTemplate` (previously after `---USER---`) is now inlined directly in Java `LlmTaskDefinition.builder().userTemplate(...)`.

### AssertionGroup Mode Binding

`AssertionGroup` gains a `mode` column (VARCHAR), establishing a one-to-one relationship between group and AgentMode:

- `error-pattern` → `WORKPLACE_STANDUP`
- `dev-progress` → `WORKPLACE_STANDUP` (new group)

`generateAssertionsAsync()` queries `groupRepository.findByMode(mode)` instead of hardcoding `findByName("error-pattern")`. Groups are processed **serially** within a session (extract → manage per group, then next group).

### New Group: `dev-progress`

| Field | Value |
|-------|-------|
| name | `dev-progress` |
| description | `The user's daily development progress, tasks completed, blockers encountered, and technologies or tools mentioned` |
| mode | `WORKPLACE_STANDUP` |

Designed for `WORKPLACE_STANDUP` mode conversations where the Learner discusses their daily work.

## User Stories

1. As a prompt engineer, I want to edit few-shot examples in a `.txt` file, so that I can iterate on prompt quality without touching Java code.
2. As a prompt engineer, I want few-shot examples and real conversation data to use the identical XML format, so that the LLM sees consistent input regardless of whether it's an example or live data.
3. As a developer, I want a single method (`toXml`) that converts conversations to XML, so that I never accidentally introduce format drift between callers.
4. As a developer, I want to optionally produce XML containing only user messages (not assistant), so that I can experiment with different prompt strategies for different assertion groups.
5. As a developer, I want the `userOnly` flag for a task to affect both few-shot examples and real conversation data from a single edit point, so that I can flip the behavior across the entire task without hunting down multiple locations.
6. As a developer, I want each LLM task's prompt files in a dedicated directory, so that I can see at a glance which templates belong to which task.
7. As a developer, I want the `---USER---` delimiter convention removed, so that prompt files have a single clear purpose and loading logic is simpler.
8. As a developer, I want to add a new assertion group by inserting a single row into `assertion_groups`, so that extending the assertion system requires zero code changes.
9. As a developer, I want assertion groups scoped to specific AgentModes, so that `DAILY_TALK` conversations don't waste LLM tokens on irrelevant extraction (e.g., dev-progress analysis).
10. As a developer, I want the existing `error-pattern` group contracted to `WORKPLACE_STANDUP` only, so that the assertion pipeline is mode-aware and no longer runs blindly for all conversation types.
11. As a learner practicing a daily standup scenario, I want the system to remember facts about my development work and technologies I use, so that the AI coach can reference them in future conversations.
12. As a maintainer, I want the JPA schema migration for the new `mode` column to happen automatically, so that I don't need to manually run SQL against existing databases.

## Implementation Decisions

### New Class: `ExampleMsgFormatter`

- **Type**: `public final class` with `private` constructor (pure static utility, no state)
- **Package**: `com.hugosol.chatagent.agent.common`
- **Public methods**:
  - `String toXml(List<MessageData> messages)` — full conversation to `<turn>` XML
  - `String toXmlUserOnly(List<MessageData> messages)` — user-only subset
  - `List<ChatMessage> parseFewShot(String content, boolean userOnly)` — `.txt` template to few-shot messages
- **Private helpers**: `escapeXml()`, `parseConversationBlock()`
- **Internal flow of `parseFewShot`**: text blocks → `parseConversationBlock` → `List<MessageData>` → `toXml`/`toXmlUserOnly` → wrap in `UserMessage`/`AiMessage`. This guarantees few-shot XML matches real data XML.

### Code Deletion

- `SessionComplete.buildLabeledMessages()` — removed
- `SessionComplete.escapeXml()` — removed
- `MemoryCueAgent.buildLabeledMessages()` — removed
- `MemoryCueAgent.buildSegmentText()` — removed
- `MemoryCueAgent.escapeXml()` — removed
- All 6 agent classes: `USER_DELIMITER` constant and `split(USER_DELIMITER, 2)` — removed

### Prompt Loading Changes

- `PromptLoader` usage changes from `load("correction.txt")` to `load("correction/system.txt")` etc.
- `PromptLoader.loadIfExists()` used for optional `examples.txt` files
- `userTemplate` strings (previously from `---USER---` split) are now Java string literals in `LlmTaskDefinition.builder().userTemplate(...)`

### AssertionGroup Schema Change

- New column: `mode VARCHAR` (nullable — JPA auto-adds via `ddl-auto=update`)
- New repository method: `List<AssertionGroup> findByMode(String mode)`
- `DataInitializer.initAssertionGroups()` seeds two groups with mode, and migrates any existing null-mode `error-pattern` row to `WORKPLACE_STANDUP`

### Assertion Pipeline Change

- `generateAssertionsAsync()` replaces `findByName("error-pattern")` with `findByMode(mode.name())`
- Groups are processed serially: for each group, extract → manage, then next group
- Cross-group merge remains intentional (embedding similarity may cluster assertions from different groups)
- When `findByMode` returns empty list, pipeline completes immediately (no-op for modes without groups)

### Refactored Agent Classes

All six agents with `---USER---` convention are refactored:

| Agent | Task(s) | Changes |
|-------|---------|---------|
| `AssertionService` | EXTRACT_TOPICS, EXTRACT_STATE, JUDGE_SAME, MERGE_ASSERTION | New directory structure, few-shot examples externalized, userTemplate inlined |
| `MemoryCueAgent` | CHAT_SWITCHES, GENERATE_MEMORY_CUE | Directory restructure, userTemplate inlined, `toXml()` replaces `buildLabeledMessages`/`buildSegmentText` |
| `CorrectionAgent` | CORRECTION | Directory restructure, userTemplate inlined |
| `LearningAgent` | MERGE_LEARNING | Directory restructure, userTemplate inlined |
| `ReportAgent` | REPORT | Directory restructure, userTemplate inlined, per-mode overrides updated |

## Testing Decisions

### Test Seam

The primary seam is **prompt template files** loaded via `PromptLoader` from the classpath. Production and test each have their own `src/*/resources/prompts/` trees. Tests verify behavior by:
- Loading restructured templates through the real `PromptLoader` (agent unit tests)
- Matching on `E2E_MARKER_*` keywords in system prompt content (WireMock E2E stubs)

No new seams are needed. The existing file-based seam is sufficient.

### What Makes a Good Test

- Test the output of `ExampleMsgFormatter` methods with known inputs, not the internal `parseConversationBlock` helper
- Test that agent constructors load restructured templates without throwing
- Test that `DataInitializer` creates groups with correct `mode` values
- E2E: verify `WORKPLACE_STANDUP` sessions still generate assertions; verify `DAILY_TALK` sessions complete without errors (assertion pipeline silently skipped)

### Test Files to Update

**Test prompt templates** (10 files restructured, 2 new):
- All files under `src/test/resources/prompts/` restructured to match new layout
- New: `assertion/extract-topics/examples.txt`, `assertion/judge-same/examples.txt`

**Java unit tests** (5 files modified):
- `PromptLoaderTest`: path strings updated
- `DataInitializerTest`: verify `mode` field in saved `AssertionGroup`, add migration test
- `MemoryAssertionRepositoryTest`: update `AssertionGroup` constructor calls
- `AssertionServiceTest`: update `AssertionGroup` constructor call in `setUp`
- Agent tests (`CorrectionAgentTest`, `MemoryCueAgentTest`, `ReportAgentTest`, `LearningAgentTest`): prompt paths updated in agent constructors

**E2E tests**: No Java changes needed. WireMock stubs unchanged.

### Prior Art

- `PromptLoaderTest` — existing pattern for testing prompt file loading
- `DataInitializerTest` — existing pattern for testing seed data creation with `ArgumentCaptor`
- `ChatAgentAssertionIT` — existing E2E for assertion generation workflow

## Out of Scope

- Parallel group processing (deferred due to merge race condition; serial for now)
- `userOnly = true` for any task (hardcoded `false`; testing deferred)
- `@Version` optimistic locking on `MemoryAssertion` (deferred until parallel processing is revisited)
- Adding assertion groups for modes other than `WORKPLACE_STANDUP`
- Refactoring the `ConversationAgent` streaming prompt path (only non-streaming sync agents in scope)
- Frontend changes (no UI impact)

## Further Notes

- The `userOnly` flag is hardcoded as `false` at two call sites in `AssertionService`: `parseFewShot(content, false)` and `ExampleMsgFormatter.toXml(segment)`. Switching to `true` requires changing both locations. This is acceptable for an experimental feature.
- The `AssertionGroup.mode` column is nullable to support JPA auto-migration of existing databases. `DataInitializer` backfills null values on startup.
- The `PromptLoader.loadIfExists()` method already exists and handles missing `examples.txt` gracefully (returns `null`, caller skips few-shot setup).
- All 6 agents' `---USER---` usage is removed. The `USER_DELIMITER` constant no longer exists anywhere in the codebase.
